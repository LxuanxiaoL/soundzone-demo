本说明中的工程相对路径以源项目根目录为起点。

双甜点：带音乐的 GitHub Pages 静态网站

构建：在工程目录执行 python build_github_pages.py。
发布目录：dist/github-pages-site
入口：index.html

本版本包含当前 music 文件夹的全部 4 个音频。打开网址后，第一首曲目已经选中；声场准备完成后，点击“开始试听”即可播放。浏览器要求先由用户点击，页面不会自行发声。访问者也可以切换曲目或添加自己的本地音频。

首页、样式、脚本、音乐和声场响应分别保存为文件，响应按当前位置加载。站点保留原来的白色界面、4/8 扬声器两方案、头部移动和中心衰减；初始中心衰减为 −1.5 dB。数值报告及下载 FIR 仍对应 0 dB 基准。

一、上传并发布

1. 在 GitHub 创建公开仓库，例如 soundzone-demo。使用下面的首次上传命令时，创建空仓库，先不添加 README、license 或 .gitignore。
2. 使用可用的 Git 命令在 PowerShell 执行下列步骤，也可以用 GitHub Desktop 上传同一目录。将 https 地址换成你刚创建的仓库地址：

Set-Location -LiteralPath '.\dist\github-pages-site'
git init
git add .
git commit -m "Publish Soundzone demo with music"
git branch -M main
git remote add origin https://github.com/你的用户名/soundzone-demo.git
git push -u origin main

3. 打开仓库 Settings → Pages，将 Source 设置为 GitHub Actions。
4. 打开 Actions → Publish Soundzone website → Run workflow，选择 main 并运行。首次 push 如果在启用 Pages 之前失败，启用后使用这一步重新运行。
5. 工作流显示成功后，在 Settings → Pages 复制访问链接，通常为 https://你的用户名.github.io/soundzone-demo/。

只发布 github-pages-site 目录的内容，让 index.html 位于仓库根目录。构建器已放入 .github/workflows/pages.yml，后续向 main 推送更新会再次发布。

当前音乐文件均小于 GitHub 普通 Git 的 100 MiB 单文件限制，其中两首超过网页上传的 25 MiB 限制，因此这套目录应通过 Git 或 GitHub Desktop 上传。音乐文件按原字节复制，不重新编码。

二、更新音乐或页面

修改工程 music 文件夹或 web 源文件后，重新执行 python build_github_pages.py，再在发布目录执行：

git add .
git commit -m "Update Soundzone demo"
git push

构建器只负责生成静态文件，不会替你创建 GitHub 仓库、登录、提交或发布。

三、本地预览

在 dist 目录运行 python -m http.server 8767 --bind 127.0.0.1，然后打开 http://127.0.0.1:8767/github-pages-site/。
静态版通过 HTTP/HTTPS 获取资源，不能以 file:// 双击 index.html 来代替网页服务器。
